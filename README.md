# DREB Football — Final Build

نسخة مستقلة جديدة من DREB Football. **لا ترفعها فوق المستودع أو موقع Netlify القديم**؛ أنشئ لها مستودعاً وموقعاً جديدين حتى يبقى المشروع القديم محفوظاً.

## المميزات

- واجهة عربية RTL بتصميم داكن ومتجاوب مع الهاتف والكمبيوتر.
- مباريات اليوم حسب التاريخ المختار، مع تبويبات المباشر والقادمة والمنتهية.
- بحث بالفرق والبطولات، تصفية حسب البطولة، وترتيب حسب الوقت أو البطولة.
- حفظ المباريات المفضلة محلياً على الجهاز.
- إحصائيات سريعة وحالة اتصال واضحة.
- تحديث تلقائي كل 90 ثانية أثناء فتح الصفحة.
- دالة Netlify تخفي مفتاح API من المتصفح، وتتحقق من التاريخ وتعالج أخطاء المصادقة والحصص والمهلة.
- لا تعرض نتائج تجريبية على أنها نتائج حقيقية.

## النشر الآمن على Netlify

1. فك ضغط الملف على جهازك.
2. أنشئ مستودع GitHub جديداً باسم `DREB-Football-Final`. ارفع **محتويات هذا المجلد** إلى جذر المستودع.
3. من Netlify اختر إضافة موقع جديد عبر Git، واربطه بالمستودع الجديد. لا تختَر الموقع القديم.
4. في إعدادات الموقع الجديد، أضف متغير البيئة `FOOTBALL_DATA_API_KEY` وضع فيه مفتاحك من football-data.org. لا تضع المفتاح داخل ملفات HTML أو JavaScript ولا تشاركه مع أحد.
5. انشر الموقع الجديد.
6. اختبر رابط الدالة: `https://YOUR-NEW-SITE.netlify.app/.netlify/functions/matches?date=2026-10-16`، واستبدل التاريخ بتاريخ صالح. يجب أن ترى JSON يحوي `matches` عند نجاح الاتصال.
7. افتح الصفحة على الهاتف وتأكد من ظهور حالة الاتصال والمباريات.

## المتطلبات والحدود

- يحتاج إلى مفتاح API صالح من football-data.org؛ التغطية والبطولات والحصص تعتمد على خطتك عند مزود البيانات.
- لا يمكن تأكيد النتائج الحية قبل النشر بمفتاح صالح.
- لا توجد حاجة إلى build command؛ ملف `netlify.toml` يحدد `.` كمجلد النشر و`netlify/functions` كدوال Netlify.

## تشغيل محلي اختياري

يتطلب Node.js وNetlify CLI:

```bash
npm install -g netlify-cli
# عيّن FOOTBALL_DATA_API_KEY في بيئة الطرفية أولاً
netlify dev
```

## الاختبارات التي أجريت على الحزمة

- فحص صياغة `app.js` و`netlify/functions/matches.mjs` بواسطة Node.js.
- اختبار الدالة بردود محاكاة: مفتاح مفقود، تاريخ غير صالح، طريقة HTTP غير مدعومة، استجابة ناجحة، مفتاح غير صالح، وحد الطلبات.
- التحقق من بنية الملفات ومراجع HTML الأساسية وسلامة أرشيف ZIP.

هذه اختبارات محلية وليست إثباتاً على نجاح الاتصال الحي؛ الاتصال الحقيقي يحتاج مفتاحاً صالحاً ونشراً جديداً على Netlify.
